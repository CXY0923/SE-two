# 裁判文书法律论证标注原型开发 Spec

## 1. 文档目的

本 spec 用于指导一个桌面 Web 可运行前端原型的设计与开发。原型服务于裁判文书“裁判理由”部分的法律论证结构标注，使用 Mock 数据模拟任务、文档、标注版本、裁定结果和导出记录，不接真实后端、不实现登录鉴权。

首版只覆盖四阶段主流程：创建标注任务、独立标注、冲突裁定、结果输出。不包含教师发布标准样例及学生独立标注入口。

## 2. 依据与范围

原型依据以下材料设计：

- 《裁判文书标记需求_按阶段组织》
- 《v1.2 中文裁判文书说理部分法律论证结构标注与图示指南》

标注对象是司法裁判文书的裁判理由部分。原型需要表达指南中的非命题要素 IS、Non，命题类型 GM、SM、GF、SF，GM 子类型 GM-L、GM-I、GM-C、GM-U、GM-M、GM-O，SM 子类型 SM、SM-C，以及 S、A、J、M、I 五种关系和关系嵌套。

## 3. 用户角色

同一用户可以拥有多个角色。

| 角色 | 原型权限 |
| --- | --- |
| 任务创建者 | 创建任务；导入文档；配置指南和标签；维护成员；分配标注者；指定裁定者；推进阶段；查看结果和导出记录 |
| 标注者 | 查看被分配文档；创建和编辑自己的命题与关系；调整图示；提交个人标注版本 |
| 裁定者 | 查看同一文档的多个标注版本；人工比对；选择某个版本内容或直接编辑；提交最终版本 |

## 4. 任务状态机

任务状态固定为：

`草稿 → 标注中 → 待裁定 → 已裁定 → 已导出`

规则：

1. 阶段只能向前推进，页面显示不可逆提示。
2. 进入“标注中”后，任务标签体系锁定；首版不提供修改或删除标签定义的入口。
3. “标注中”允许追加文档和标注者；新增分配不覆盖已有标注版本。
4. 文档删除、已提交版本删除、关系类型删除不在首版支持范围内。
5. 进入“已导出”后，最终结果只读；如需重标，提示重新创建任务。
6. 单个文档可以分配给多个标注者；每名标注者保存独立版本。
7. 只有一份标注版本时仍进入裁定页，由裁定者确认或修改。

## 5. 信息架构与页面

### 5.1 任务总览页

以表格或卡片展示任务名称、指南版本、文档数、当前阶段、标注进度、裁定进度、创建者和更新时间。支持按阶段、案例类型筛选并进入任务详情。

### 5.2 创建任务页

采用四步向导：

1. **基本信息**：任务名称、任务说明、案例类型、指南版本。
2. **导入文档**：Mock 支持 PDF、Word、纯文本、复制粘贴；展示文档名称、案例类型和自动提取的裁判理由范围；允许人工修正起止位置。
3. **标签体系**：展示固定标签树和关系列表。创建任务进入标注阶段后锁定。
4. **人员分配**：选择标注者、每份文档的标注人数和裁定者；可按文档或案例类型批量分配，并可在标注中追加人员。

### 5.3 任务详情页

顶部显示阶段进度条和不可逆提示；中部显示文档列表、分配情况、标注/裁定进度；右侧显示当前阶段操作，例如“开始标注”“进入裁定”“查看结果”“导出”。

### 5.4 标注工作区

采用可调节宽度的三栏布局：

- **左栏：原文与命题列表**。展示裁判理由文本。拖选文本后创建命题；命题按原文起始位置自动编号，列表显示完整原文、标签和状态。支持修改文本、修改标签、删除后重新创建、撤销和重做。
- **中栏：命题属性与操作**。展示字符索引、原文、一级标签、二级标签和编辑记录。允许先创建无标签命题，再补充标签。
- **右栏：论证图示**。命题用仅显示序号的矩形节点表示；关系用指南规定的关系节点和连线表示。支持选中图元后建立关系或拖拽连线创建关系，支持 S/A/J/M/I 及嵌套关系，支持缩放、拖拽节点和刷新布局。

三栏双向联动：点击命题定位并高亮原文及图节点；点击图节点定位命题；删除或重建命题后同步更新关系。

### 5.5 裁定页

左侧显示原文和裁定条目，右侧按标注者分栏展示命题、边界、标签和关系结果。首版不强制自动定位差异，由裁定者人工比对；裁定者可以选择某个版本、逐项采用内容或直接编辑，提交后生成最终版本。

### 5.6 结果输出页

展示最终只读的命题表、关系表和论证图示。Mock 支持 PNG/JPG/SVG、Excel、JSON 和压缩包导出；导出时可填写文件名，显示进度和完成状态，并记录下载用户、时间、指南版本。

## 6. Mock 数据模型

核心实体：

- `Task`：任务信息、指南版本、当前阶段、成员和文档集合。
- `Document`：名称、案例类型、原始文本、裁判理由起止索引、分配关系。
- `AnnotationVersion`：某标注者针对某文档提交的一份独立版本。
- `Proposition`：命题编号、原文、字符起止索引、一级标签、二级标签和所属版本。
- `Relation`：关系类型、参与对象、嵌套结构和所属版本。
- `Adjudication`：裁定记录、采用来源、人工修改内容、裁定者和时间。
- `ExportRecord`：格式、文件名、指南版本、导出人、下载时间和状态。

建议的前端引用关系为：`Task -> Document -> AnnotationVersion -> Proposition/Relation`，最终版本由 `Adjudication` 指向并固化；`ExportRecord` 只引用最终版本，不产生可编辑副本。

## 7. 标注与校验规则

### 7.1 命题

- 字符索引使用半开区间 `[start, end)`，基于裁判理由文本。
- 命题按原文起始位置排序，从 1 开始编号。
- 删除命题后采用删除并重新创建，不保留旧编号。
- 同一版本内命题编号唯一；编号变化时关系引用同步更新。
- 命题可先无标签保存；提交前必须完成一级标签，GM 和 SM 还必须完成对应子标签。

### 7.2 关系

- S、A、M 为有向关系；J、I 至少包含两个参与对象。
- M 的参与对象必须满足个别判断与一般判断之间的类型约束。
- J 只表示“缺一不可”的合取，不自动把多个独立 S 合并为 J。
- 关系可以嵌套关系单元，但不得引用不存在或已删除的命题。
- 图示是关系数据的可视化，不单独维护第二套逻辑数据。

### 7.3 版本与提交

- 标注者只能编辑自己的草稿版本；提交后锁定，需复制为新草稿才能修订。
- 裁定者可以采用任一标注版本内容，也可以直接编辑生成最终版本。
- 推进阶段前校验文档范围、命题标签、关系引用和必填人员。
- 阶段推进、提交、裁定、导出和下载写入前端操作日志。

## 8. 内置 Mock 场景

原型至少内置一个完整示例任务，包含：

- 一份已提取裁判理由的文书；
- 两名标注者的独立版本；
- 标签差异、边界差异和关系差异；
- 至少一个嵌套结构，例如 `S(M(J(P1,P2),P3),P4)`；
- 一个已裁定并可导出的最终版本。

## 9. 验收标准

### 9.1 主路径

用户可以完成：

`创建任务 → 导入文档 → 配置标签和人员 → 标注命题 → 建立关系 → 提交两个版本 → 裁定 → 查看图示 → 导出 JSON/Excel/图片 → 查看下载记录`

### 9.2 边界行为

1. 未完成必填项时不能推进阶段，并展示明确原因。
2. 已提交版本和已导出结果不可直接修改。
3. 命题、关系、标签和图示始终保持同步。
4. 只有一个标注版本时仍可进入裁定页并提交最终版本。
5. 阶段推进后，前一阶段入口变为只读或不可用。

## 10. 非目标

- 真实用户登录、服务端鉴权和权限持久化。
- 真实 PDF/Word 解析和裁判理由自动抽取算法。
- 真实文件上传、云端存储和下载服务。
- 真实 Excel/JSON/图片生成服务；首版用前端 Mock 导出反馈。
- 一致性指标计算、自动差异定位和专家线下协同。
- 教师/学生教学模式。
